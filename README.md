# 現場の健全性診断（genba-check）

**🔗 今すぐ試す:** https://genba-check-283196730351.asia-northeast1.run.app/?utm_source=github （登録不要・約3分）

エンジニアが、今いる開発現場の健全性を20問で自己診断するWebアプリ。

- 仕様（質問・採点・結果ページ）: [docs/questions.md](docs/questions.md)
- 質問データと採点ロジック: `src/lib/diagnosis.ts`
- バックエンドなし。回答はブラウザ内だけで処理する

## 開発

```bash
npm install
npm run dev   # http://localhost:3000
npm run build
```

## MCP サーバー（Claude Code から診断する）

`mcp/` に、同じ20問と採点を MCP ツールとして提供するサーバーがある（stdio）。質問データと採点は `src/lib/diagnosis.ts` をそのまま import しており、Webアプリと結果は同じ。本体とは別パッケージなので、Webアプリのビルドやイメージには影響しない。

診断は次の流れで進む。

1. AI が `get_questions` を呼ぶと、サーバーが Claude Code の確認画面（MCP の elicitation）にプライバシーの説明を直接表示する。表示するのはクライアントなので、AI が説明を省くことはできない。同意したときだけ、20問を AI に返す。診断を始めるたびに説明を見せるため、以前に同意していても、呼ばれるたびに確認画面を出す
2. AI が Claude Code の質問用の画面（選択肢から選べる画面）で、4問ずつ聞く。サーバーは「問いの文言を変えず、質問用の画面で4問ずつ聞く」よう AI に指示する。ただし、聞き方を決めるのは AI なので、指示どおりになるとは限らない
3. AI が回答を `score_answers` に渡し、サーバーが採点する。20問すべてそろっていないと採点しないので、問いが抜けた場合は気づける。また、確認画面に対応したクライアントでは、このサーバーのプロセスでまだ同意を得ていない場合（`get_questions` を経ずに呼ばれた、または断ったあとに呼ばれた場合）は、採点の前にも確認画面で同意を確かめ、同意がなければ採点しない。同意を得たかどうかは、サーバーのプロセスが動いている間だけ覚えておき、ファイルには残さない。サーバーからは会話の区切り（`/clear` など）が見えないので、会話ごとではなくプロセスごとに覚える。そのため、同じプロセスで一度同意していれば、採点の前の確認画面は出ない。ただし、その後の確認画面で同意が得られなかった場合（断った・閉じた・時間切れ・中断・表示できなかった・エラー）は、どの理由でも以前の同意を取り消す。確認画面に対応していないクライアントでは、同意の確認はできないので、問いも採点結果もそのまま返す。回答に不備があるときは、確認画面を出す前に不備を返す。なお、採点の前の確認画面の時点で、回答はすでにツールの引数として AI の提供元に送られている。確認画面と断ったときの案内でもそう伝え、断った場合も行わないのは採点だけだと明示している

MCP サーバー自体は回答を保存・外部送信しない（ファイル書き込み・ネットワーク通信をせず、回答をログに出力しない。標準エラー出力に出すのは、起動時の1行と、確認画面で想定外のエラーが起きたときのエラーコードだけで、回答は含まない）。ただし回答は会話やツールの引数としてAIの提供元に送信され、クライアント側の会話記録にも残ることがある。ブラウザ内だけで処理するWebアプリとはこの点が違う。

**使える環境**

| 環境                                 | 使えるか                                                                                                                                           |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| ターミナルの Claude Code（`claude`） | 使える                                                                                                                                             |
| VS Code 版の Claude Code             | **使えない**。確認画面を表示せずに自動で閉じてしまうため。サーバーは「確認画面を表示できなかった」と返し、ターミナルの対話モードで使うよう案内する |
| `claude -p` などの非対話モード       | 使えない。VS Code 版と同じく確認画面を表示できないので、中止して対話モードで使うよう案内する                                                       |
| 確認画面に対応していないクライアント | 使えるが、プライバシーの説明は結果の先頭に置いて AI に伝えさせる形になるので、伝わるかどうかは AI 次第になる                                       |

確認画面を表示できたかどうかは、返事が人には不可能な速さ（0.1秒未満）で返ってきたかどうかで推測している（VS Code 版の自動の断りは実測で0.006〜0.012秒）。「断る」「閉じる」だけでなく「同意」も同じで、0.1秒未満で自動的に返ってきた同意は、同意として扱わない。ただし、これは速さによる推測なので、時間をかけて自動で承諾するクライアントやフックは見分けられない。そのため、同意の返事を受け取ったときも、AI には「同意の返事を受け取った（ユーザーが読んだかどうかまでは確かめられない）」とだけ伝えている。推測が外れても困らないよう、どちらの案内にも、もう一方だった場合の手がかりを添えている（人が断ったとみなした場合は対話モードで使う方法、表示できなかったとみなした場合は「断ったのであれば何もしなくてよい」）。

確認画面への返事は10分まで待ち、それを過ぎたら中止して、やり直し方を案内する。ツールの呼び出しを中断すると、確認画面の要求も取り消す。なお、クライアント側にもツールの呼び出しの時間制限があり、説明を読んでいる時間もこれに含まれる。Claude Code の既定は約27時間（`MCP_TOOL_TIMEOUT` で変えられる）なので問題にならないが、60秒などで打ち切るクライアントでは、説明を読み終える前にツールの呼び出しが切れることがある。

| ツール          | 内容                                                                                                                                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_questions` | 確認画面に対応したクライアントでは、プライバシーの説明への同意を確認画面で取ったうえで、20問を、カテゴリ・逆転の問いかどうか・聞き方の指示と一緒に返す                                                               |
| `score_answers` | 20問への回答（よくある／たまにある／ない）を受け取り、総合スコア・ラベル・カテゴリ別スコア・優先して見る項目・本人が取れる行動を返す。このサーバーのプロセスでまだ同意を得ていなければ、先に確認画面で同意を確かめる |

### よく使うコマンド（早見表）

どれもリポジトリのルートで実行する。詳しくは下の各節。

| やりたいこと                 | コマンド                                                                                                                    |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 初めて使う（ビルドして登録） | `npm --prefix mcp install && npm --prefix mcp run build`<br>`claude mcp add genba-check -- node "$(pwd)/mcp/dist/index.js"` |
| pull や編集のあとに反映する  | `npm --prefix mcp install && npm --prefix mcp run build` → Claude Code の `/mcp` で再接続                                   |
| 登録されているか確かめる     | `claude mcp get genba-check`（Claude Code の中なら `/mcp`）                                                                 |
| 登録を外す                   | `claude mcp remove genba-check -s local`（`--scope user` で登録した場合は `-s user`）                                       |
| 診断する                     | ターミナルの Claude Code で「genba-check で今の現場を診断して」と頼む（VS Code 版では使えない）                             |

登録は、登録したあとに開いた Claude Code のセッションから使える。登録より前から開いていたセッションでは呼べないので、開き直す。

### ビルドと登録

Node.js 20.19 以上（20 系）または 22.12 以上が必要（テストで使う Vite の要件）。

```bash
npm --prefix mcp install
npm --prefix mcp run build   # 型チェック（tsc）のあと mcp/dist/index.js を作る。型エラーがあれば止まる
npm --prefix mcp test        # 採点が docs/questions.md の仕様どおりかを確かめる
```

Claude Code への登録は、次の **どちらか一方** を実行する（両方登録すると同じ名前が2つのスコープに残る）。パスは絶対パスで指定するので、リポジトリのルートで実行する。

このプロジェクトでだけ使う場合：

```bash
claude mcp add genba-check -- node "$(pwd)/mcp/dist/index.js"
```

どのプロジェクトからでも使う場合：

```bash
claude mcp add --scope user genba-check -- node "$(pwd)/mcp/dist/index.js"
```

登録できたかは `claude mcp list`、または Claude Code 内の `/mcp` で確認できる。登録を外すときは `claude mcp remove genba-check -s local`（user スコープなら `-s user`）。

### 更新したとき

登録したサーバーはビルド済みの `mcp/dist/index.js` を動かすので、`src/lib/diagnosis.ts`（質問や採点）や `mcp/` を変えても、再ビルドするまで反映されない。Webアプリと結果をそろえるため、pull や編集のあとは依存パッケージを入れ直してから再ビルドし、Claude Code の `/mcp` から genba-check を再接続する（または Claude Code を再起動する）。依存が変わっていなければ install はすぐ終わるので、毎回まとめて実行してよい。

```bash
npm --prefix mcp install && npm --prefix mcp run build
```

### 使い方の例

ターミナルの Claude Code で次のように頼む。

```
genba-checkで今の現場を診断して
```

プライバシーの説明の確認画面が出るので、同意する。そのあと Claude が質問用の画面で4問ずつ聞くので、選択肢から選んで答える。20問答え終わると、次のような結果を伝える。

```
総合スコア：65点（注意）
項目別スコア：残業文化 0 / 変更管理 100 / 扱いの公正さ 100 / 時間への配慮 100 / 心理的安全性 100 / 人への関心 0
優先して見る項目：残業文化（0点）
本人が取れる行動：長く働くことが前提になっていたり、評価につながったりする場面があるようです。…
```

回答がすでに手元にある場合は、`score_answers` にまとめて渡すこともできる（このサーバーのプロセスでまだ同意していなければ、採点の前にプライバシーの説明の確認画面が出る。同じプロセスで一度同意していれば出ない）。

```
genba-check で採点して。1〜4 は「よくある」、18〜20 は「たまにある」、それ以外は「ない」。
```

## デプロイ（Cloud Run）

```bash
./scripts/deploy-cloud-run.sh
```

- 対象プロジェクトは `gcloud config` の現在のプロジェクト（`PROJECT_ID` で上書き可）
- 本番URL（OG画像のURLに使う）はスクリプトが組み立てて、ビルド時に `.env.production` として渡す。独自ドメインにしたら `SITE_URL=https://... ./scripts/deploy-cloud-run.sh`
- `next.config.ts` の `output: "standalone"` が前提（Dockerfile がこれを使う）
